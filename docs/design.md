# 园区需量控制与储能协同组件——设计说明

本组件完全本地运行：进线、储能、负载遥测均由内存仿真器产生，不依赖任何外部
服务或网络。所有决策、状态维护与审计均为确定性计算。

## 1. 包结构

| 包 | 职责 |
| --- | --- |
| `telemetry` | 多来源遥测接入、校验（乱序/重复/越界/跳变/校验和）、状态维护 |
| `demand` | 需量窗口（固定锚点对齐）、梯形积分统计、窗口末预测、月度峰值台账 |
| `storage` | 储能能量账本（效率模型）、SOC 对账、温度降额、可用能力评估 |
| `controller` | 决策核心：模式切换、储能调度、负载优先级削减、人工强制、审计日志 |
| `sim` | 本地园区仿真器与场景运行器（`Plant` + `Runner`） |
| `cmd/demo` | 端到端演示入口 |

## 2. 需量口径与窗口规则

### 2.1 窗口

- 窗口长度固定为 15 分钟（`Config.WindowLength`），按当地时区（默认
  `Asia/Shanghai`）当天 00:00 为锚点对齐，即 00:00、00:15、…、23:45。
- 窗口为左闭右开 `[Start, End)`。跨天窗口（23:45–次日 00:00）按起点
  所在自然日/月归档，跨天、跨月口径一致、可解释。

### 2.2 当期需量

- 需量 = 窗口起点到当前时刻进线平均有功功率（kW）。
- 统计方法为**梯形积分**：相邻功率样本间按梯形面积积分能量，再除以时长；
  末点零阶保持到窗口结束，样本缺失区间用最近一个点覆盖（有明确的覆盖
  失败返回，绝不拿空数据硬算）。
  恒定功率下平均即为该功率；线性爬升段取起止均值。

### 2.3 窗口末预测

- 预测假设“最后一个样本的功率零阶保持到窗口结束”：
  `predicted = (当期能量 + 末功率 × 剩余时间) / 窗口总时长`。
  这是“负载维持现状”口径，物理含义明确且对控制保守。

### 2.4 历史峰值

- 每个已关闭窗口结算出一个需量值；月度峰值取该月所有已关闭窗口的最大值。
- 窗口结算按窗口起点去重：同一窗口重复回放不重复追加记录，也不会重复抬升
  峰值；只有同一窗口更高的结算值才更新。
- 窗口数据不足以可靠结算（起点未覆盖）时记 `window_unclosed_missing_data`
  故障审计，**不**写入峰值。

## 3. 遥测接入与拒绝原因

样本结构 `telemetry.Sample{ID, Source, AssetID, Kind, TS, Value, Checksum}`：

- `ID` 全局唯一（仿真器用 `步号|来源|资产|物理量` 生成），用于重复/回放去重；
- `Checksum` 可选，为 `source|asset|kind|unixns|value` 的 CRC32-IEEE（hex）。

样本可乱序、重复、延迟到达。拒绝原因（`telemetry.Reason`）彼此可区分：

| 原因 | 触发条件 |
| --- | --- |
| `duplicate` | 相同 ID 已处理；或同资产同类型同时间戳同值 |
| `conflict` | 相同 ID 负载不同；或同时间戳出现不同取值 |
| `stale` | 落后最新已接受样本超过 `MaxStale`（默认 10min） |
| `future` | 时间戳超前当前时间超过 `MaxFuture`（默认 5min） |
| `expired` | 早于保留窗口（默认 24h） |
| `missing_field` | ID/来源/资产/类型/时间戳缺失，或类型未知 |
| `out_of_range` | 非有限值（NaN/Inf）或超出该物理量配置范围 |
| `jump` | 与 120s 内相邻样本相比变化率超过配置上限 |
| `checksum` | CRC32 校验失败 |

关键性质：

- 被拒绝样本**不进入**决策所用序列；拒绝事件带原因与解释。
- 批量入口先按时间戳排序再做相邻跳变检查，因此乱序整批提交、逐条提交、
  并发分片提交三种入口，对同一批输入的接受/拒绝结论唯一。
- 所有已处理 ID（含被拒绝的）登记去重；重启/回放同一批数据不会二次生效。

## 4. 储能调度与效率模型

### 4.1 能量账本

- 电池能量 `E = SOC × CapacityKWh`（默认 100kWh）。
- 交流侧功率符号：**正=充电，负=放电**。
- 效率模型（默认 η充=η放=0.95）：
  - 充电：进电池能量 `ΔE = P·dt·η充`，故 `ΔSOC = P·dt·η充/Cap`；
  - 放电：电池耗能 `|ΔE| = |P|·dt/η放`，故 `ΔSOC = P·dt/(η放·Cap)`（P<0）。
- 功率段按样本 ID 积分去重；乱序段（时间戳回退）拒绝并记故障审计，
  因此重复回放不重复累计、也不漏积分。

### 4.2 SOC 对账

- 首个 SOC 样本初始化账本；之后每个上报 SOC 与积分推算值对账。
- 偏差超过容忍度（默认 0.05）产生 `SOCMismatch`：
  写 `soc_energy_mismatch` 审计、冻结对储能的信任、控制器进入保守模式，
  直到人工核查后 `Ledger.ClearMismatch()`/重新标定。
- 小偏差做观测值与模型的轻校正（取中点），以模型积分为主。

### 4.3 能力与约束

- 备用下限 `MinSOC`（默认 0.2）：可放电池能量只计算下限以上部分，
  到下限后放电能力为 0；`MaxSOC`（默认 0.95）对称约束充电。
- 温度线性降额：
  - [5℃, 45℃] 满功率；
  - [-10℃, 5℃) 与 (45℃, 55℃] 线性降到 0；
  - ≤-10℃ 或 ≥55℃ 截止；温度未知也禁止功率动作。
- 放电功率取三者最小值：额定×降额、窗口剩余时间内**可持续**功率
  （`可放交流电量/剩余小时数`）、当前需量缺口。

### 4.4 调度顺序

1. 预测需量 ≥ 动作线（上限−启动裕量，默认 790kW）：
   先让储能按上述可持续功率放电顶住；
2. 储能放电后仍有缺口（到备用下限/温度受限/能量撑不到窗口末）：
   按优先级削减可调负载；
3. 预测需量 ≤ 释放线（上限−恢复裕量，默认 770kW）且连续 `HoldTicks`
   （默认 2）个 tick 安全：停放电、按稳定条件恢复负载；
4. 负荷低谷且需量余量 ≥ `ChargeHeadroomKW`（默认 120kW）时，
   在“充完电仍不触线”的约束下允许充电。

## 5. 降载优先级与稳定条件

- 每个负载有 `Priority`（数字小先削）、保底功率 `MinKW`、额定 `RatedKW`。
  默认顺序：`hvac-1(1)` → `evcp-1(2)` → `pump-1(3)`。
- 削减只切“上限与保底之差”的可调部分，按缺口逐档下压；
  全部可削减完仍有缺口时记录“reduction gap remains”，保守报警但不突破口径。
- **滞回**：动作线 790 与释放线 770 之间为死区，不启动动作也不恢复；
  恢复必须连续 `HoldTicks` 个 tick 预测安全，恢复原因固定 `stable_release`。
  功率指令按 0.1kW 量化，同一窗口相同设定值不重复下发，抑制抖动与重复动作。

## 6. 人工强制操作

- `controller.ApplyManual(ManualOverride{Actor, Target, Kind, ValueKW, Reason})`
  支持：储能强制充/放/解锁、负载强制削减/满投/解锁。
- 人工操作期间：
  - 被强制对象严格执行人工指令，自动控制不得覆盖；
  - 自动需量保护仍对**其他**对象运行（缺口仍由储能/非人工负载兜底）；
  - 每条人工操作立即写 `manual` 审计（含操作人、原因、值、时间）。

## 7. 故障保守策略

以下任一条件成立即进入 `conservative` 模式：

- 进线遥测失联（超过 `StaleGrid`，默认 2min）或从未到达；
- 时间大幅回退（超过 `ClockJumpTolerance`，默认 10min）；
- 窗口需量无法可靠计算（起点未覆盖）；
- 储能 SOC 与能量账本对不上。

保守动作（宁可多限电，不允许突破需量上限）：

- 储能立即置空闲（不充不放），不依赖不可信设备；
- 全部可调负载压到保底功率；
- 保守状态每个窗口留一次 `conservative_shed_held` 审计，无新指令也留痕；
- 失联/时钟恢复后，仍需预测回到释放线以下并连续 `HoldTicks` 个 tick
  才退出，保证平稳恢复、不状态跳变、不重复/漏动作。

## 8. 审计与重启续跑

- `controller.Journal` 为 JSONL 顺序追加日志，类别含
  `command / reject / manual / fault / peak / soc / lifecycle`。
- 每条记录可带 `DedupKey`（窗口+目标+值），同键只落盘一次；
  因此同输入重放不会重复下发动作、重复抬峰值或重复累计能量。
- 重启续跑流程：
  1. `LoadJournal(path)` 读回历史审计，`BeginReplay(entries)` 建去重水位；
  2. `RestoreState(storage.State)` 恢复 SOC 能量基线与已处理样本 ID；
  3. 回放历史遥测与 tick（`Tick` 在 replay 下只重建内存状态，不写盘、不下发）；
  4. `EndReplay()` 回到正常控制。

## 9. 本地验证方法

```bash
# 端到端演示（高峰越限、储能放电、优先级削减、人工强制、失联保守、恢复、峰值）
go run ./cmd/demo

# 全部单元/仿真测试
go test ./...

# 竞态检测（并发接入与决策用例）
CGO_ENABLED=1 go test -race -count=1 ./...
```

测试覆盖（`sim/*_test.go`、各包 `*_test.go`）：

- 乱序/重复/延迟遥测与全部拒绝原因；三种入口结论唯一性、并发去重；
- 阈值与滞回边界（死区不动作、动作线触发放电、稳定计数恢复、充电门槛）；
- 储能效率积分与重复不累计、SOC 对账、备用下限、温度降额/截止；
- 进线失联保守与平稳恢复、时间跳变；
- 人工强制尊重与审计、解锁后自动恢复；
- 重启续跑：SOC 与峰值一致、动作不重复、审计文件不追加；
- 跨天/跨月窗口对齐与归档。

测试日志（`-v`）逐步打印输入样本、拒绝原因、当期/预测需量、SOC、
储能模式、削减负载、下发指令及判定依据。

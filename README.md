# 园区用电需量控制与储能协同（Go）

纯本地、无外部服务依赖的园区需量控制与储能协同组件：多来源遥测校验与状态
维护、滚动窗口需量统计与历史峰值、储能效率能量账本与调度、可调负载优先级
削减与滞回恢复、失联/时间跳变/SOC 异常的保守处理、审计与重启续跑。

## 快速开始

```bash
go run ./cmd/demo
go test ./...
CGO_ENABLED=1 go test -race -count=1 ./...
```

需要 Go 1.25+（在 Go 1.26 下验证通过）。

## 代码地图

- `telemetry/`：遥测样本、拒绝原因（duplicate/conflict/stale/future/expired/
  missing_field/out_of_range/jump/checksum）、并发安全的状态存储。
- `demand/`：15 分钟锚点对齐窗口、梯形积分平均需量、窗口末零阶保持预测、
  跨天/跨月一致的月度峰值台账。
- `storage/`：充放电效率能量账本、SOC 对账、温度降额、备用下限、能力评估。
- `controller/`：normal/manual/conservative 三种模式决策、优先级削减、
  滞回稳定条件、人工强制、JSONL 审计日志、重放与状态恢复。
- `sim/`：本地园区仿真器（进线=负荷+负载+储能功率，SOC 与账本同效率模型）、
  场景运行器与全部场景测试。
- `cmd/demo/`：可直接运行的端到端演示。
- `docs/design.md`：需量口径、储能模型、降载优先级、故障保守策略与验证方法。

## 核心约定

- 储能交流功率：正=充电，负=放电；充电 `ΔSOC=P·dt·η充/Cap`，
  放电 `ΔSOC=P·dt/(η放·Cap)`。
- 默认需量上限 800kW、窗口 15min；动作线 790kW、释放线 770kW，
  恢复需连续 2 个 tick 安全。
- 调度顺序：预测越限先储能放电（受备用下限/温度/可持续能量约束），
  不足再按优先级 `hvac-1 → evcp-1 → pump-1` 削减；低谷余量充足才充电。
- 任何不可观测/不一致（进线失联、时钟回退、SOC 对不上账）都进入保守模式：
  储能空闲、可调负载压到保底，恢复需满足稳定条件。
